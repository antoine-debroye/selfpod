Podhost

Your shows, self-hosted — in a workshop, not a dashboard.

A design language for Podhost, a single-container podcast server. Warm, crafted, and built so that dropping a file in a folder is the whole workflow. This document is the complete design system and a high-fidelity pass over every screen in the spec.

01

Design System

Self-hosted tools usually look like they were built for the person who built them. Podhost is for someone who records a show in a closet studio and wants their infrastructure to feel like a quiet, well-made instrument — not a server console. The system below is built around warmth (paper, ink, terracotta), a single editorial serif for voice, and clarity for the technical bits that matter.

Upload

For when you'd rather not touch the filesystem at all. Drag-and-drop straight into a show; the server validates extensions against the spec's supported list, streams to temp, then atomically moves into the show folder and triggers an immediate scan — no waiting for the next polling cycle.

08

Activity Log

The spec's single most important UX requirement: every failure that was invisible until a podcast app broke must show up here, in plain language. Each scan is a row; errors expand into actionable sentences that name the configured PUID and the exact path — not a stack trace.
